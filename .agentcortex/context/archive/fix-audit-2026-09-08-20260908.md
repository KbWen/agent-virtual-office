## Decisions

### D-1: `server.mjs` honours `OFFICE_STATUS_DIR` (F-02) → consolidated: L2 hook-integration

- **Decision**: adopt the `vite.config.js` resolution in the production server, and announce an active
  override in the startup banner.
- **Reason**: the two transports resolved the same input differently, and spoofing HOME for the whole
  process was the only alternative (which is what the E2E tests do). `path.dirname(STATUS_PATH)` is
  already what `scanAndMerge`/`getSessionStats` scan, so one knob covers session discovery too.
- **Alternatives**: leave the asymmetry (nothing is *broken* — the Docker compose file bind-mounts
  `${HOME}/.claude` and works today).
- **Tension**: the archived ship note for the dev-server flag says it "cannot reach a shipped office".
  Read precisely, that claim is about the *vite plugin's* status API being registered under
  `configureServer` only, and about the browser payload (`grep -rl OFFICE_STATUS_DIR dist/` → no
  match, still true). This adds no fabrication capability — it re-points a file the existing writer
  already owns — but it IS a new decision about `server.mjs`, so it is recorded here for the owner
  rather than buried in a diff.
- **Impact**: `server.mjs`, and a new startup log line when the variable is set.

### D-2: `awaiting-approval` gets a dedicated behavior, not a reused idle one (F-05) → consolidated: L2 hook-integration

- **Decision**: new desk-bound `await-approval` behavior + hourglass glyph.
- **Reason**: the audit suggested `'alert'`/`'idle'`/`check-phone`-style states. `check-phone` and
  `stretch` are lounge DESTINATIONS in `movementSystem.js`'s `BEHAVIOR_LOCATIONS`, so either would have
  walked the agent to the sofa in response to a status signal — position is state in this product.
  `scratch-head` is `blocked`'s, and AVO-167 deliberately separates the two.
- **Alternatives**: reuse `scratch-head` (collapses the AVO-167 distinction); return null (freezes
  whatever behavior preceded the wait, which for a hook-sent wait can be `typing`).
- **Impact**: `classify.js`, `store.js` STATUS_BEHAVIOR_MAP, `AgentCharacter.jsx`, both locales.

## Security Findings

- 2026-09-08 /review: 0 findings. No secrets, credentials or connection strings added; no dependency
  manifest change; no new endpoint, auth path or trust boundary.
- Net TIGHTENING at the untrusted-payload boundary: the codex hook previously passed `task`/`label`/
  `hint` through as `value || null` with **no length cap** and had no `reasonCode` validation at all.
  Both now use the canonical `statusContract` sanitizers (200-char cap; `reasonCode` enum-validated
  against `BLOCKED_REASONS`), so a crafted Codex payload can no longer push an unbounded string or an
  arbitrary reason code into the store.
- `OFFICE_STATUS_DIR` in `server.mjs` (D-1) is not a new attack surface: anyone able to set the process
  environment already controls the process. It re-points a file the existing `/api/status` writer owns,
  and the pre-existing writability fail-fast still runs against the resolved directory.
- Shell hook: the `date` output is gated by an all-numeric test before arithmetic, and `SEQ` reaches the
  status file through `jq --arg` (no shell interpolation into the JSON).
- Dockerfile: the two added `COPY` lines ship published source only; no `.env`, key material or
  `node_modules` enters the runtime image.
