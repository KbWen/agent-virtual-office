## 1. System & Architecture Overview

- **Core Stack**: React 19 + Vite 8.2 + Zustand 5 + Tailwind CSS 4. CommonJS package wrapper with native ESM (`.mjs`) server/config execution, Node >= 22. Pure SVG canvas rendering without heavy 2D canvas/WebGL game engines.
- **Entry Points**:
  - `bin/cli.js`: CLI binary (`npx agent-virtual-office` / `npx agent-virtual-office serve`).
  - `server.mjs`: Standalone production HTTP/SSE server providing `/api/status`, `/api/event`, `/api/lang` with file-backed persistence.
  - `vite.config.mjs`: Dev server middleware mirroring production endpoints and serving frontend HMR.
- **Module Architecture**:
  - `src/components/`: SVG rendering components (`PixelOffice.jsx`, `AgentCharacter.jsx`, `AgentInspector.jsx`, `ControlPanel.jsx`, `NarrowRoster.jsx`, `ActivityFeed.jsx`, `OfficePet.jsx`).
  - `src/systems/`: Pure logic domain engines (`store.js`, `movementSystem.js`, `officeLife.js`, `classify.js`, `behaviorEngine.js`, `officePalette.js`, `doorClaims.js`, `moodEngine.js`).
  - `src/inference/`: Ambient heuristics and event triggers (`inferStatus.js`, `desktopNotifier.js`, `idleGapInfer.js`, `workflowHandoff.js`, `agentRouter.js`).
  - `src/utils/`: Shared transport contracts (`statusContract.mjs`, `statusFields.js`, `normalizePost.mjs`).
  - `public/hooks/`: External agent hook adapters (`office-status-hook.js`, `office-status-codex.js`, `generic-llm-bridge.js`).

## 3. Detailed Finding Breakdown

### F-01: Independent Monotonic Clocks in Vite Dev Server (`nextSeq`) (P1)
- **Problem**: `src/utils/statusContract.mjs` explicitly specifies:
  > *"Single monotonic clock for the whole server process. server.mjs's /api/event writer shares THIS counter — two independent counters writing the same status file can emit a lower _seq after a same-ms burst, tripping the cross-channel stale-drop guard (inferStatus.js high-water mark). One process = one clock."*
  In `server.mjs`, both `/api/status` and `/api/event` correctly share `statusContract.mjs`'s monotonic clock. However, in `vite.config.mjs:78-83`, a duplicate `let _seqLast = 0; function nextSeq() ...` was declared locally. In `vite.config.mjs:583`, `/api/event` uses this local counter, whereas `/api/status` calls `normalizePost()`, which advances the counter inside `statusContract.mjs`.
- **Impact**: In Vite development mode, high-frequency webhooks alongside hook status updates can generate out-of-order sequence timestamps, resulting in legitimate status updates being silently dropped by `inferStatus.js`.
- **Fix**: In `vite.config.mjs`, import `nextSeq` from `./src/utils/statusContract.mjs` and remove the duplicate local definition.

---

### F-02: Client Chunk Exceeding 500 kB (500.94 kB) (P2)
- **Problem**: `npm run build` prints:
  `dist/assets/index-57AOv7hn.js 500.94 kB │ gzip: 157.99 kB`
  `(!) Some chunks are larger than 500 kB after minification.`
- **Impact**: Exceeds default Vite bundle warning. Current bundle budget allows up to 546 kB (+10%), so CI passes, but continued feature growth will soon breach the hard budget.
- **Analysis**: The app currently bundles:
  1. Complete dual-language dictionaries (`en.json` 24.5 kB + `zh-TW.json` 24 kB = 48.5 kB raw JSON).
  2. Canvas screenshot generation (`dailyCard.js`).
  3. Extensive SVG path definitions and matrix math across all furniture and character costumes.
- **Fix Options**:
  - *Option A*: Defer secondary features (e.g. `dailyCard.js` / canvas export) via `React.lazy()` / dynamic `import()`.
  - *Option B*: Split vendor chunks (React/Zustand) from application logic using `build.rollupOptions.output.manualChunks`.

### F-05: Bridge UI Missing Modern Agent Statuses (P3)
- **Problem**: `public/bridge-ui.js` only provides toggle buttons for `['working', 'blocked', 'done']`. Modern statuses `planning` (AVO-101) and `awaiting-approval` (AVO-167 / cyan ring) are missing from the interactive grid.
- **Impact**: Developers testing panel mode or embedding integrations cannot easily trigger `awaiting-approval` via the browser bridge UI without manual console injection.
- **Fix**: Extend the button loop in `createAgentCard()` to include `planning` and `awaiting-approval`.
